# Version 5.2.0 PostgresSQL Database Scripts

## Upgrade_to_Ver520_PostgreSQL.sql
Takes an existing Version 5.1.0 PostgreSQL database and brings it up to Version 5.2.0. PostgreSQL port of `Upgrade_to_Ver520.sql` (the SQL Server upgrade script), matching it change for change:
- Adds `GCS Page Load URL Expiration Minutes` (default 10) and `GCS Download URL Expiration Minutes` (default 60), so signed GCS URLs can be shorter-lived for page images, thumbnails and download links than for files the page keeps requesting. Updates the help text of `GCS Signed URL Expiration Minutes` (default 240), which now covers only those long-running files (PDF, audio, video, page turner).
- Adds `GCS Restricted Streaming URL Expiration Minutes` (default 60), a separate cap for files a restricted item's page keeps requesting (PDF, audio, video). Previously every signed URL on a restricted item was capped at `GCS Restricted URL Expiration Minutes` (15), which broke playback and reading past 15 minutes for authorized users. Updates that setting's help text to say it now caps only page images, thumbnails and download links.
- Adds `SobekCM_Add_Automatic_Institution`, and changes `SobekCM_Save_New_Item`, `SobekCM_Save_Item`, `SobekCM_Save_Item_Behaviors` and `SobekCM_Mass_Update_Item_Behaviors` to call it. Institution aggregations added automatically during an item save (named 'Added automatically') used to be inserted as a bare row. They now go through `SobekCM_Save_Item_Aggregation`, so they inherit the ALL collection's facets, result views, result fields, GroupResults flag and editing permissions like any other new collection.
- One-time backfill: every non-deleted Institution aggregation with no result views gets the ALL collection's result views, result fields, facets (only if it has none) and editing permissions (only for users and groups without a row yet). GroupResults is left alone.
- Seeds `SobekCM_Item_Aggregation_Default_Result_Fields`, but only if the table is empty. The 5.x complete scripts never populated it, so databases built since 5.0 fell back to a list hardcoded in the engine. Uses the list from the SQL Server 5.0 upgrade (Publication Date at display order 3), plus the VRA Core fields (Material, Measurements, Technique, Style Period, Cultural Context, Inscription), for every result type.
- Adds `SobekCM_Save_Item_Aggregation_Result_Fields`, used by the collection admin Results tab to save the result fields shown in a collection's brief view and thumbnail hover tooltip. The fields are stored against the collection's BRIEF and THUMBNAIL result views. Saving with the defaults option removes them, so the collection goes back to the install-wide defaults.
- Lets the users admin screen see and change whether a user is active. `mySobek_Get_User_By_UserID` gains an optional `p_include_inactive` parameter (default false, so existing callers are unchanged) and returns `isActive`. `mySobek_Get_All_Users` returns `isActive` too. Both are dropped and recreated, since their signature or return type changes. Adds `mySobek_Set_User_Active`. A deactivated user cannot log on by any method.
- Adds user news: HTML messages shown in a banner at the top of every page for the people they target, until each person closes them. A message can target everyone (including visitors who are not logged on, who close it with a cookie), all logged-on users, administrators (system, portal, user and news administrators, never host administrators), collection managers and specific user groups. New tables `mySobek_News`, `mySobek_News_User_Group_Link` and `mySobek_News_User_Dismissed`. New functions `mySobek_Get_Pending_News`, `mySobek_Dismiss_News`, `mySobek_Get_All_News`, `mySobek_Save_News`, `mySobek_Delete_News` and `mySobek_Reset_News_Dismissals`. Adds the News Administrator role (`mySobek_User.IsNewsAdmin`), returned by `mySobek_Get_User_By_UserID`; `mySobek_Update_User` is dropped and recreated with an optional `p_is_news_admin` parameter (NULL leaves it unchanged). Also adds release news for the administrators, shown for 90 days, announcing the 5.2.0 upgrade.
- Adds a System User flag (`mySobek_User.IsSystemUser`), for accounts that must never be locked out (e.g. service/integration accounts). Not setable anywhere in the UI - defaults to false and is only ever set directly against the database. `mySobek_Get_User_By_UserID` returns it (signature unchanged, so just `CREATE OR REPLACE`); when set, the users admin screen shows "System users cannot be deactivated" instead of the deactivate checkbox. `mySobek_Get_All_Users` also returns it (dropped and recreated, since its return type changes) - system users are hidden entirely from the users admin list for anyone who isn't the top-level admin (Host Administrator if hosted, otherwise System Administrator), who can choose to show them via a new System Users filter.
- Adds a per-item "serve files locally" flag (`SobekCM_Item.Serve_Files_Locally`, default false). When set, the item's whole file folder is served from local disk even under GCS Hybrid / GCS Full, for the few items whose viewer loads sub-files by relative path (web site, HTML with its own images, open textbook). Replaces the old rule that treated any item with a WEBSITE / HTML / OPEN_TEXTBOOK / OPEN_DIVISIONS viewer registered as local, which wrongly caught items with an unused HTML viewer. `SobekCM_Get_Item_Details` and `SobekCM_Builder_Get_Minimum_Item_Information` return it (signatures unchanged, so just `CREATE OR REPLACE`); new `SobekCM_Set_Item_Serve_Files_Locally`. The save functions are unchanged, so re-saving from METS never clears it. One-time backfill flags items with a WEBSITE / OPEN_TEXTBOOK / OPEN_DIVISIONS viewer, or a non-excluded HTML viewer whose attribute names an .htm/.html file.
- Updates `SobekCM_Database_Version` to 5.2.0.

## Ver520_DB_Complete_PostgreSQL.sql
Not created yet: 5.2.0 is still in development. At release it will be built from the Version 5.1.0 complete script with this upgrade folded in. Until then, build a new database from `Version 5.1.0/Ver510_DB_Complete_PostgreSQL.sql` and run `Upgrade_to_Ver520_PostgreSQL.sql` against it.

## Notes on Upgrading
If you are running 5.1.0, run `Upgrade_to_Ver520_PostgreSQL.sql` against your existing database. If you are running an older version, apply the earlier PostgreSQL upgrade scripts first (see `Version 5.1.0/Upgrade_to_Ver510_PostgreSQL.sql`).
